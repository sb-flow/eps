# Construction Radar UZ — MVP

Рабочий front-end прототип веб-приложения для базы строительных объектов Узбекистана. Данные автоматически подготовлены из файла `База_строительных_объектов_Узбекистан_2026 (2).xlsx`.

## Уже реализовано

- 372 карточки объектов из листов `Объекты` и `Региональные объекты`.
- 796 записей участников из листа `Участники регионов`, связанных с проектами по ID Shaffof.
- Глобальный поиск по объекту, адресу, региону, компаниям, проектировщикам, подрядчикам, ИНН, телефонам и ID Shaffof.
- Отдельный фильтр по роли компании: застройщик, заказчик, проектировщик, подрядчик или другой участник.
- Нечёткий поиск компаний: нормализация ООО / MCHJ / кавычек и юридических форм, сопоставление кириллицы/латиницы, подсказки ближайших совпадений с количеством связанных объектов.
- Фильтры по региону, сегменту, стадии, приоритету, наличию контактов и координат.
- Три режима: таблица, карточки, Google Maps.
- 331 объект уже имеет координаты в исходной Excel-базе.
- Карточка объекта с участниками, контактами, ИНН, площадями, сроками, источниками и следующим шагом.
- Загрузка спецификаций XLSX/XLS/CSV/PDF/DOCX. Excel/CSV получает быстрый предпросмотр через SheetJS.
- Файлы MVP сохраняются в IndexedDB браузера и привязываются к объекту.

## Запуск

Нельзя открывать `index.html` напрямую через `file://`, потому что браузер заблокирует загрузку JSON. Запустите локальный сервер из папки проекта:

```bash
./serve.sh

# либо
python3 -m http.server 8080
```

Затем откройте `http://localhost:8080`.

## Google Maps

В приложении нажмите **Google Maps API** и вставьте ключ Google Maps JavaScript API. Ключ сохраняется только в localStorage текущего браузера.

Для production:

1. Создать отдельный ключ в Google Cloud.
2. Включить Maps JavaScript API.
3. Ограничить ключ доменами приложения.
4. Хранить конфигурацию через environment/build config, а не пользовательский localStorage.

## Рекомендуемая production-архитектура следующего этапа

- **Frontend:** Next.js + TypeScript + Tailwind / shadcn.
- **Backend:** Supabase/PostgreSQL или PostgreSQL + FastAPI/Next API.
- **Auth:** Supabase Auth / Clerk / корпоративный SSO.
- **Storage:** Supabase Storage / S3 для спецификаций, паспортов и техдокументации.
- **Search:** PostgreSQL trigram + full-text; позднее embeddings для смыслового поиска и совпадений названий компаний.
- **Maps:** Google Maps + серверное геокодирование только для записей без координат.
- **AI:** извлечение позиций спецификации, определение раздела (ОВиК/ВК/ЭОМ/ИТП/ХС), предварительный подбор и оценка потенциала поставки.
- **Tasks:** задачи, ответственные, дедлайны, история изменений и триггеры по стадии проекта.
- **Integrations:** Bitrix24, источники реестров/мониторинга, email, Telegram/WhatsApp при необходимости.

## Структура

- `index.html` — основной интерфейс.
- `styles.css` — дизайн CRM.
- `app.js` — фильтрация, поиск, карта, карточки и локальные спецификации.
- `data/projects.json` — нормализованные карточки объектов.
- `data/participants.json` — база участников.
- `data/meta.json` — метаданные выгрузки.
- `CODEX_PROMPT.md` — следующий запрос для Codex, чтобы превратить MVP в полноценное приложение.


## Как продолжить в Codex

1. Распакуйте проект и откройте папку как рабочий репозиторий в Codex.
2. Передайте Codex содержимое `CODEX_PROMPT.md` как задачу.
3. Попросите сначала сохранить текущий UX и импорт данных, затем переносить приложение на Next.js/TypeScript.
4. На production-этапе вынесите Google Maps API key в переменные окружения и замените IndexedDB на Storage + БД.

Текущий MVP специально сделан без backend, чтобы можно было быстро проверить структуру интерфейса и логику поиска на реальной базе до проектирования серверной части.
