# Задача для Codex: превратить MVP Construction Radar UZ в production web app

Возьми текущую папку проекта как функциональный прототип интерфейса. Сохрани UX и набор функций, но перенеси приложение на Next.js + TypeScript и PostgreSQL/Supabase.

## Этап 1 — перенос интерфейса

1. Создай Next.js App Router проект.
2. Разнеси интерфейс на компоненты: SidebarFilters, SearchBar, ViewSwitcher, ProjectTable, ProjectCards, ProjectMap, ProjectDrawer, SpecificationUpload.
3. Создай типы Project, Participant, Organization, Contact, Specification, Task, ProjectEvent.
4. Импортируй текущие `data/projects.json` и `data/participants.json` как seed.
5. Сохрани глобальный поиск и текущий нечёткий поиск компаний: нормализация юрформ, кириллица/латиница, подсказки совпадений, фильтрация по роли (застройщик/заказчик/проектировщик/подрядчик/другой участник).

## Этап 2 — база данных

Создай таблицы:

- projects
- organizations
- project_participants
- contacts
- specifications
- specification_items
- project_sections
- tasks
- project_events
- sources
- users
- user_organizations

Проект должен поддерживать роли участника: заказчик/девелопер, генподрядчик, проектировщик, субподрядчик, поставщик, технический заказчик, оператор.

## Этап 3 — спецификации + AI

После загрузки XLSX/PDF/DOCX:

1. Сохранить оригинал в Storage.
2. Извлечь строки спецификации.
3. Определить инженерный раздел: ОВиК, ТМ, ИТП, ХС, ВК, ЭОМ, АОВ, автоматика.
4. Создать позиции specification_items.
5. Подготовить AI-анализ: производитель, артикул, описание, количество, предполагаемый аналог, вероятность совпадения, комментарий инженера.
6. Не изменять исходные данные автоматически без подтверждения пользователя.

## Этап 4 — Google Maps

- Использовать координаты из базы, если они есть.
- Геокодировать только объекты без координат и сохранять результат в БД.
- Кластеризовать маркеры.
- Клик по маркеру открывает ProjectDrawer.
- Фильтры таблицы и карты должны использовать одно состояние.

## Этап 5 — совместная работа

- Авторизация.
- Организации/команды.
- Комментарии и история изменений.
- Задачи внутренним и внешним пользователям.
- Статусы: Новый, Контакт найден, Связались, Получена спецификация, Подбор, КП, Переговоры, Заказ, Проигран, Отложен.
- Автоматические задачи по дедлайну/стадии/отсутствию активности.

## Этап 6 — Bitrix24

Сделать адаптер интеграции, чтобы:

- создавать/обновлять компанию и контакт;
- создавать сделку по объекту;
- передавать ID объекта и URL карточки;
- синхронизировать ответственного и статус;
- логировать ошибки и избегать дублей по ИНН + нормализованному названию.

## Acceptance criteria

- Поиск < 300 мс на 10 000 объектов.
- Одинаковые фильтры для таблицы, карточек и карты.
- Возможность открыть объект по постоянному URL `/projects/[id]`.
- История всех изменений критичных полей.
- Импорт текущей Excel-базы повторяемый и идемпотентный.
- Названия компаний сопоставляются по ИНН, нормализованному имени, fuzzy score и ручному merge.
- Поиск одной и той же компании работает при вариантах ООО/MCHJ, кавычках, сокращениях и типичных кириллических/латинских написаниях.
- Карта, таблица и карточки используют единый набор фильтров, включая роль компании.
